## 0. 最终音乐方案

本卡**取消网易云模块**。

不再使用：

- 网易云 iframe
- 网易云歌曲 / 歌单 URL 解析
- 网易云歌曲 ID
- 网易云页面嵌入
- 网易云账号 / Cookie / 凭据
- 单独 PAGE2 音乐页

改为：

**直接播放用户上传到本仓库的 MP3 文件。**

音乐仍然属于同一张单页 MVU 的底部区域，不新增页面。

## 1. 音乐文件来源与目录

用户后续会自行把正式 MP3 上传到仓库。

建议统一目录：

`media/music/`

静静不得擅自下载、转码、重命名、压缩或替换用户上传的 MP3。

运行时只允许通过仓库云端 URL 读取这些音频。

正式构建时优先使用**固定 commit 的 raw URL**，不要长期依赖 `main` 浮动 URL。

若施工期间歌曲 commit 尚未最终冻结，可先把曲库来源抽象成 manifest，最终由绒绒在整卡装配前锁定 commit URL。

---

## 2. 曲库 manifest

允许新增：

`mvu/music-manifest.v1.json`

用途仅限描述仓库曲库，不属于业务世界书。

建议结构：

```json
{
  "version": 1,
  "default_track": "theme",
  "tracks": [
    {
      "id": "theme",
      "title": "变形钢姬主题曲",
      "artist": "待用户确定",
      "path": "media/music/<filename>.mp3",
      "url": "<fixed-commit-raw-url>"
    }
  ]
}
```

规则：

- `id` 唯一且稳定。
- `default_track` 必须指向真实存在曲目。
- 不从文件名猜歌名 / 歌手；以用户最终提供的信息为准。
- 不把 MP3 Base64 塞入角色卡或 JS。
- manifest 只存元数据与 URL。

## 3. 播放器架构

必须保持**一个全局 `<audio>` 实例**。

禁止：

- 每次切歌新建一堆 audio 元素
- 返回锁屏时销毁播放器
- DOM 重绘时重建播放器导致歌曲从头播放
- 每楼消息生成第二套播放器
- 同时播放两首歌

允许：

- 单实例切换 `src`
- 读取当前曲目
- 播放 / 暂停
- 上一首 / 下一首
- 点击列表选歌
- 当前播放曲目高亮
- 必要的进度 / 音量控制（保持极简）

聊天切换 / MVU 模块真正销毁时，才清理全局 audio 实例与监听器。

---

## 4. 主题曲自动启动规则

用户要求：进入 MVU 时自动播放主题曲。

但 Android WebView / SillyTavern / 浏览器可能限制无手势 autoplay，因此不得只写：

```js
audio.autoplay = true
```

然后假设一定成功。

### 正确实现

锁屏本来就要求用户点击中央进入 MVU。

**必须把这一次点击同时视为音乐播放用户手势。**

流程：

1. 用户点击锁屏中央进入。
2. 同一个 click / pointer 事件链中显示 MVU。
3. 若当前无正在播放歌曲，则设置默认主题曲。
4. 立即调用一次 `audio.play()`。
5. 若成功，正常播放。
6. 若被环境拒绝，捕获 Promise rejection，不得抛未处理错误、不白屏、不循环重试。
7. UI 在底部播放器处显示一个极简“点击播放”状态，等待用户再次手动点击。

不得采用绕过浏览器 autoplay 限制的黑科技。

### 返回锁屏

返回锁屏：

- **不断播**。
- 再次进入 MVU：若歌曲仍在播放，不从头重启。

## 5. MVU 底部音乐区最终 UI

音乐区放在内页背景**最底部 / 何博玟与薇震天脚部区域**。

不另开页面。

整体应是一条很薄的半透明机械 dock，视觉优先级低于中央双竖条。

默认收起状态建议只显示：

- 当前曲名
- 播放 / 暂停
- 上一首
- 下一首
- 一个展开曲库按钮

不要常驻大封面。

不要使用厚重播放器卡片遮住背景。

---

## 6. 曲库选择：上下滑动

点击展开后，在底部 dock 上方展开一个**小型纵向曲库抽屉**。

要求：

- 曲目纵向排列。
- Android 手指上下滑动选择。
- `overflow-y: auto`。
- 不允许横向滚动。
- 每条曲目点击热区至少 44px 高。
- 当前曲目明显但克制地高亮。
- 点击歌曲后直接切换并播放。
- 切换后可自动收回，也可保留展开；优先选择不挡中央竖条的方案。
- 曲目较多时只滚动列表，不把整个 MVU 撑高。

不得把曲库做成横向轮播。

---

## 7. 与中央阵营 UI 的层级

音乐播放器属于辅助层。

视觉优先级固定：

1. 背景：何博玟 × 薇震天
2. 中央：汽车人 / 霸天虎双竖向阵营好感计
3. 底部：音乐 dock

音乐抽屉展开时也不得覆盖中央好感计主要可视区。

建议最大展开高度使用响应式限制，例如：

`max-height: min(32vh, 240px)`

具体值可按实机适配调整，但不得占满屏幕。

## 8. 音频状态与容错

播放器至少正确处理：

- `loadedmetadata`
- `canplay`
- `play`
- `pause`
- `ended`
- `error`

建议行为：

- 单曲结束后默认播放下一首；末尾可循环到第一首。
- 某一首加载失败，只标记该曲失败，不摧毁整个播放器。
- 不因为一首 404 导致 MVU 白屏。
- URL 不合法时跳过并给出轻量 UI 状态。
- 网络中断后允许用户重新点击播放。
- 不做无限自动重试。

不要求离线下载歌曲。

## 9. 状态保持

在同一聊天 / 同一 MVU 生命周期中，应尽量保持：

- 当前曲目
- 当前播放时间
- 播放 / 暂停状态
- 音量（若实现）

普通 DOM 更新、消息新增、阵营好感刷新、详情卡开合都不得让音乐重新从 0 播放。

返回锁屏也不得重置。

仅在：

- chat change
- 模块销毁
- 用户明确切歌

时进行对应必要处理。

## 12. QA 必测

至少覆盖：

1. 锁屏点击进入后，主题曲能在允许的环境中立即开始播放。
2. autoplay 被 WebView 拒绝时，不报错、不白屏，出现可点击播放状态。
3. 返回锁屏不断播。
4. 再次进入不从头播放。
5. 阵营数值刷新时不断播。
6. 打开 / 关闭阵营详情时不断播。
7. 上下滑动曲库正常。
8. 点击其他歌曲可以切歌。
9. 当前曲目高亮正确。
10. 单曲结束自动进入下一首。
11. 某一 MP3 404 / 加载失败不会摧毁播放器。
12. 同一时刻只有一个 audio 实例 / 一首歌曲有声。
13. Android / SillyTavern 不出现横向滚动。
14. 音乐 dock 与展开曲库不遮死中央双竖向好感计。
15. chat change / 模块销毁后旧实例与监听器被正确清理。
