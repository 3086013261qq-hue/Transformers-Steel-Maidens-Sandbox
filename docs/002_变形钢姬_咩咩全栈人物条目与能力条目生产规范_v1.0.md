# 《变形钢姬》咩咩全栈人物条目与能力条目生产规范 v1.0

> 状态：正式生产规范
> 适用：`worldbook/characters/main/`、`worldbook/characters/other/`、`worldbook/abilities/`
> 上游：咩咩制卡包·全栈 v1.0.0 `chara-v1` / `<核心设定:名称>`
> 人物基线：`docs/001_变形钢姬_人物总名册_v0.3.md`
> 名称替换：`manifest/character-name-replacements.v1.json`
> 原则：保留咩咩原生骨架，只做赛博坦机械生命的字段语义适配；不得另造角色 schema。

## 一、角色条目：严格 `chara-v1`

角色条目必须使用：

```text
<【角色名】character>
名字:
性别:
印象:
发色:
发型:
瞳色:
身材:
胸部:
上衣:
下装:
配饰:
鞋子:
心理模型:
- Trauma:
- Defense:
- Trigger:
- Need:
对话范例:
"……"
"……"
"……"
</【角色名】character>
```

### 硬规则

1. 栏位名称、顺序、`心理模型` 四槽、三句 `对话范例` 均不得增删或改名。
2. 不新增“核心信念 / 人格层 / 行为逻辑 / 能力 / 技能”等自创栏位；这些内容应折回 `印象`、四槽心理模型、对话表现，或拆到独立核心设定条目。
3. `Trauma / Defense / Trigger / Need` 必须保持英文槽名及顺序，不得改成赛博坦术语。
4. 能力不得塞入 `chara-v1`；能力另建 `<核心设定:角色名·能力>`。
5. 正式人物条目只使用娘化名；原名只存在于资料核对、QA 与映照 manifest。

## 二、赛博坦字段语义适配

`chara-v1` 字段名不变，只改变填写语义。

### 名字
填写现行娘化名，例如 `何博玟`、`薇震天`。

### 性别
统一以世界内事实书写。普通赛博坦角色建议：

`女性（双重性征）`

不得写“由男性娘化”“原本是男性”等元叙事。

### 印象
承担角色整体锚点：阵营/长期职责 + 第一性格印象 + 最醒目的机体气质。必要时可压入一条最重要的人际或历史身份，但不得写成长篇背景。

推荐颗粒度：1～3 句。

### 发色
字段名必须保留，但不得凭空给无毛发赛博坦人造人类头发。

填写方式：
- 无毛发角色：`无毛发；头部主装甲色为……`
- 确有辫须、缆线、发束感机械结构者：写其机械结构颜色。

### 发型
字段名必须保留，语义改为“头冠 / 头部装甲轮廓 / 天线 / 鳍片 / 缆线或须状结构”。

示例：`蓝色高冠式头部装甲，侧后方有短鳍片与天线，无人类毛发。`

不得为角色凭空添加长发、双马尾等与电影视觉无关的人类发型。

### 瞳色
写光学镜颜色、数量与形态。

示例：`蓝色双目光学镜，狭长而明亮。`

独眼角色必须明确独眼结构。

### 身材
承载人物卡必须具备的体格数据与女性机体轮廓：
- 身高；
- 质量/体重（官方无精确值时允许按载具与机体级别合理估算，并在资料阶段标注推定）；
- 机体规格；
- 肩、腰、胯、四肢比例；
- 装甲厚薄与整体女性化体态。

不得把战力直接等同于胸腰胯或身高。

### 胸部
保留用户人物卡标准：必须包含字母罩杯等效视觉体量；同时用赛博坦世界语言描述胸甲/活体机械结构。

推荐形式：`F罩杯等效视觉体量；胸甲……，结构与车窗/前舱/装甲件……`

“罩杯”仅用于制卡视觉尺度，不代表赛博坦文明使用人类内衣尺码。

### 上衣
字段名保持，内容改写为“上半身装甲与载具零件布局”。

推荐起句：`不穿人类布制服装；……`

可描述胸甲、肩甲、背甲、车窗、格栅、排气管、机翼、旋翼、炮塔等。

### 下装
字段名保持，内容改写为“骨盆、腰胯、大腿、小腿的下半身装甲结构”。

推荐起句：`不穿人类布制服装；……`

### 配饰
只写有视觉与身份意义的非基础结构：
- 汽车人/霸天虎徽记；
- 面罩；
- 天线；
- 轮组；
- 肩炮挂点；
- 缆线、辫须；
- 纪念涂装；
- 特殊工具与非性征常规武装的外置部件。

不得把性征武装详细机制塞入此栏。

### 鞋子
字段名保持，内容改写为“足部装甲 / 轮组 / 履带 / 起落与抓地结构”。

推荐起句：`无独立鞋具；……`

例如赛薇可写足部轮组形成滑行式战斗站姿。

## 三、心理模型：完全保留咩咩原生四槽

### Trauma
定义角色长期人格结构中的核心创伤、失败、失去、羞辱、背叛、战争记忆或无法消化的责任。

- 不要求角色患有临床 PTSD；
- 不得把普通“弱点”冒充 Trauma；
- 远古/长期战争角色尤其要考虑时间尺度与记忆重量。

### Defense
角色在压力、威胁、亲密、失败或创伤被触及时最常用的心理防御方式。

例如：控制、冷漠化、幽默、否认、理性化、攻击性、过度承担、撤退、服从、夸张自信。

### Trigger
会稳定触发其核心情绪/防御/行为模式的情境。

Trigger 应具体可 RP，不写泛词，如“危险”“敌人”。优先写：被质疑领导资格、同伴再次牺牲、被当成无灵魂机器、失去通讯控制权等。

### Need
角色深层而稳定的心理需要，不等于“想赢”“想杀敌”“需要 Energon”。

优先写：被信任、保有自主权、被承认为完整生命、证明自己值得追随、有人愿意留下、获得赎罪机会等。

### 四槽联动要求

四槽必须形成因果链：

`Trauma → Defense → Trigger → Need`

不得四句互不相关。

## 四、对话范例

- 固定三句；
- 使用中文；
- 每句应体现角色真实语言节奏、立场和心理模型；
- 不写旁白，不写“她说道”；
- 不写同义三连；
- 不强行加入网络口癖或现代人类俚语，除非角色长期在人类社会形成该语言习惯。

## 五、能力条目：独立 `<核心设定>`

能力条目不进入 `chara-v1`，统一使用：

```text
<核心设定:【角色名】·能力>
……能力正文……
</核心设定:【角色名】·能力>
```

### 能力正文必须覆盖的内容

能力核心可按角色需要组织，但原则上需要交代：

- 机体规格与基础能力；
- 替代形态 / 变形特性；
- 专属性征武装模块；
- 常规武装；
- 战斗方式与战术定位；
- 特殊技术、遗产权限或独有系统；
- Energon / 火种 / 热负荷 / 弹药等续航约束；
- 受损、过载、拆离或失联后果；
- 明确限制与不可做之事。

这些不是必须逐字作为固定小标题；能力条目仍是咩咩全栈的“核心设定正文”，可按角色内容自然编排，但必须信息闭环。

### 性征武装写法

- 使用世界内正式术语“性征武装 / 性征武装模块”；
- 描述生体机械结构、展开、供能、控制、拆离、损伤与修复；
- 不展开性行为描写；
- 不是每名角色都可拆离；
- 不把所有角色做成炮；
- 武器类型须遵循 `docs/001_变形钢姬_人物总名册_v0.3.md` 的现行锚点。

## 六、人物与能力的职责边界

### 角色条目负责

- 她是谁；
- 她看起来是什么样；
- 她给人的整体印象；
- 她为什么形成现在的人格；
- 她在什么情况下会怎样反应；
- 她如何说话。

### 能力条目负责

- 她能做什么；
- 为什么能做到；
- 如何战斗 / 变形 / 使用专属系统；
- 代价、限制和受损后果是什么。

禁止在两条中大段重复同一信息。

## 七、触发与装配

- 人物条目归 `主要角色` 或 `其他角色` 区；
- 能力条目归 `核心设定` 区；
- 人物与同名能力条目应共享角色娘化名作为关键触发词；
- 原名可保留为工程层检索 alias，但正式剧情输出必须由 `manifest/character-name-replacements.v1.json` 替换为娘化名；
- 正式 worldbook 正文不得出现“娘化”“原男性”“基于电影角色改编”等元叙事。

## 八、生产前检查清单

每名角色进入正式世界书前必须确认：

1. 标签为 `<角色名character>`，字段顺序完全正确；
2. 无新增/删除 `chara-v1` 栏位；
3. Trauma / Defense / Trigger / Need 完整且成因果链；
4. 三句对话存在且能区分角色；
5. 无凭空人类发型/服装；
6. `身材` 有身高、质量/体重与机体轮廓；
7. `胸部` 有字母罩杯等效视觉体量；
8. 光学镜、头冠、胸甲、下肢/足部结构与电影视觉相符；
9. 能力已拆到独立 `<核心设定:角色名·能力>`；
10. 性征武装与 v0.3 总名册一致；
11. 能力存在真实负荷、损伤与边界；
12. 原名不进入正式人物正文和正式剧情输出。

- 能力条目各 1；
