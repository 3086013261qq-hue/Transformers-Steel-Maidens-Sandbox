# 《变形钢姬》咩咩全栈人物条目与能力条目生产规范 v1.5

> 状态：审计后正式生产规范（人物关系字段内嵌版）
> 基础格式：继承 v1.4 的机械外貌字段、五项上游继承字段、心理模型与能力条目规则。
> 当前人物上游：`docs/001_变形钢姬_人物总名册_v0.4.md`
> 目的：严格保持咩咩全栈人物条目顺序，并把长期稳定的人际关系作为人物条目固定字段，而不是额外拆出“关系层”。

## 一、正式人物模板

正式人物条目严格使用以下顺序：

```text
<【角色名】character>

名字:

性别:

阵营:

定位:

变形载具:

外貌锚点:

印象:

头部主色:

头部结构:

光学镜:

机体比例:

胸甲结构:

上身装甲:

下身装甲:

外置结构:

足部结构:

性征武装模块:

心理模型:
- Trauma:
- Defense:
- Trigger:
- Need:

人际关系:
- ……

对话范例:
"……"

"……"

"……"

</【角色名】character>
```

硬性顺序为：**心理模型 → 人际关系 → 对话范例**。

`人际关系` 不得前移到 `印象`、外貌或身份字段之前，也不得塞入 `Trauma / Defense / Trigger / Need` 四槽内部。

## 二、人物总名册仍是五项上游真源

角色条目以下五项继续从现行人物总名册直接继承：

`阵营 / 定位 / 变形载具 / 外貌锚点 / 性征武装模块`

其中：

- `外貌锚点` 必须逐字一致；
- 其他四项不得在人物条目中私自创造第二套业务事实；
- 若发现上游字段本身错误，必须先修人物总名册，再同步下游人物条目与能力条目。

`人际关系` 不属于人物总名册五项继承字段，它由角色长期历史、稳定编队、明确指挥链、长期敌对与已经成立的关系事实综合生成。

## 三、人际关系字段规则

### 3.1 只写长期稳定、真正影响 RP 的关系

优先写：

- 长期战友、搭档、姐妹/组合伙伴；
- 稳定上下级或指挥协作；
- 宿敌、旧阵营、背叛后形成的长期裂痕；
- 明确雇佣、护卫、医疗、技术、情报与伴随作战关系；
- 对角色心理和行为长期产生影响的关键对象。

不得为了凑数量，把“见过一次、同属一个阵营、参加过同一场战斗”硬写成挚友、姐妹、导师或私人仇敌。

### 3.2 数量与颗粒度

- 通常每人写 2～4 条；
- 关系稀疏的次要角色可写 1～3 条；
- 可以写具体人物，也可以在确有必要时写稳定群体关系，如“Constructicon 同伴”“汽车人难民与平民”；
- 每条关系需要说明互动性质，而不是只写“朋友 / 敌人 / 同事”。

### 3.3 双向一致性

若 A 的关系明确声称 B 是“最亲密搭档、长期宿敌、直接上下级、固定组合成员”等强关系，则 B 的条目不得给出相反事实。

双向关系允许视角不对称，例如：

- A 尊敬 B，但 B 只是把 A 当可靠部下；
- A 想取代 B，而 B 把 A 当必须防备的副官；
- A 把某关系理解成雇佣，B 把同一关系理解成创造者权限。

这种不对称属于角色立场差异，不算事实冲突。

## 四、关系字段与时间线的职责边界

**不建立独立“关系层”。**

人物条目的 `人际关系` 只保存当前角色设定中长期稳定、可跨场景调用的关系基线。

时间线负责：

- 关系何时建立；
- 何时背叛、决裂、转阵营；
- 某一阶段信任如何升降；
- 死亡、失联、复活或重构对关系状态的改变；
- 某部电影内一次性事件造成的临时态度。

因此，时间线可以改变关系状态，但不得另造一套与人物条目长期事实互相冲突的“关系数据库”。

## 五、业务字段与工程资料继续分离

五项继承字段与 `人际关系` 都只允许写世界内可成立的业务事实。

禁止把以下工程措辞写进正式人物关系：

- “原作中 / 电影里 / 玩具设定”；
- “娘化后 / AU里”；
- “为了制卡 / 为了方便AI”；
- 资料来源等级、制作决策或工程备注。

原名只用于工程检索与 `manifest/character-name-replacements.v1.json`，正式人际关系一律使用娘化名。

## 六、机械外貌、心理模型与对话规则保持不变

- 机械外貌字段继续使用：`头部主色 / 头部结构 / 光学镜 / 机体比例 / 胸甲结构 / 上身装甲 / 下身装甲 / 外置结构 / 足部结构`；
- 禁止恢复人类中心的 `发色 / 发型 / 瞳色 / 上衣 / 下装 / 鞋子` 等字段；
- `心理模型` 固定为 `Trauma / Defense / Trigger / Need`，顺序不可变；
- `对话范例` 固定三句中文对话；
- `人际关系` 位于心理模型之后、对话范例之前。

## 七、能力条目规则继续沿用 v1.4

能力条目仍使用：

`<核心设定:角色名·能力> ... </核心设定:角色名·能力>`

继续执行 v1.4 已锁定的：

- 机体/替代形态；
- 性征武装；
- 常规武装与辅助系统；
- 战斗/工作方式；
- Energon、热负荷、弹药、接口、处理能力等资源约束；
- 损伤反馈；
- 明确不可做之事；
- Headmaster、组合形态、KSI、分裂体等质量/火种连续性边界。

本次 v1.5 不修改任何能力条目正文。

## 八、正式名称与时间线

- 文件名、人物标签、`名字:`、`人际关系`、能力标签及正式剧情只使用娘化名；
- 原名仅用于工程检索、来源核对和替换键；
- 正式 `<world_timeline>` 输出必须执行原名 → 娘化名替换；
- 时间线只推进关系状态，不新建独立关系层。

## 九、v1.5 QA 检查

每个人物条目至少检查：

1. 恰好存在一个 `人际关系:` 字段；
2. 字段顺序严格为 `Need → 人际关系 → 对话范例`；
3. 关系条目使用娘化名；
4. 强关系双向不矛盾；
5. 不把普通同阵营写成挚友/姐妹/私人宿敌；
6. 关系稀疏角色允许使用稳定群体关系，不强行编造私人关系；
7. 人际关系不得取代心理模型，也不得重复能力机制；
8. 时间变化留给 `<world_timeline>`；
9. 五项 roster 继承字段、机械外貌、三句对话与能力文件保持原封版规则；
10. 仓库不再生产或维护独立 `RELATION_LAYER`。

## 十、版本结论

v1.5 在 v1.4 基础上只新增并锁定：

- `人际关系` 为正式人物条目固定字段；
- 正确字段位置：心理模型后、对话范例前；
- 69 名角色全部补齐长期稳定关系；
- 强关系执行双向一致性审计；
- 正式取消独立关系层概念。

后续人物层与时间线生产以 **v1.5 + 人物总名册 v0.4** 为唯一现行基线。
