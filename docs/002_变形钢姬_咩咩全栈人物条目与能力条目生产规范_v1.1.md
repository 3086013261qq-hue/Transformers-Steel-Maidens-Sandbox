> 状态：正式生产规范 / FORMAT_LOCKED
> 适用：`worldbook/characters/main/`、`worldbook/characters/other/`、`worldbook/abilities/`
> 上游：咩咩制卡包·全栈 v1.0.0 `chara-v1` 人物骨架与 `<核心设定:名称>` 能力拆分逻辑

> 核心原则：保留咩咩人物条目的结构顺序、心理模型和对话范例；仅将容易诱发人类外貌幻觉的外观字段替换为赛博坦原生字段。

## 二、与咩咩 `chara-v1` 的一一对应关系

本规范不增加外貌槽位数量，只将九个容易产生人类外观误读的字段一一替换：

- `发色` → `头部主色`
- `发型` → `头部结构`
- `瞳色` → `光学镜`
- `身材` → `机体比例`
- `胸部` → `胸甲结构`
- `上衣` → `上身装甲`
- `下装` → `下身装甲`
- `配饰` → `外置结构`
- `鞋子` → `足部结构`

`名字 / 性别 / 印象 / 心理模型 / 对话范例` 的职责保持咩咩原生逻辑不变。

## 三、字段填写规则

### 名字
只写现行娘化名。正式人物正文不得出现原名作为显示名。

### 性别
普通赛博坦角色统一写世界内事实：`女性（双重性征）`。不得写“娘化”“原男性”等元叙事。

### 印象
1～3 句概括：长期职责、第一性格印象、机体气质、最关键的历史/关系锚点。不得塞技能表。

### 头部主色
写头部装甲、机械缆线、冠状结构的主要颜色与点缀色。不得写“发色”，也不得凭空生成毛发。

### 头部结构
写头冠、面罩、天线、鳍片、机械须、辫须、缆线、翼片等真实结构。若无毛发，直接不讨论“头发”。

### 光学镜
写颜色、数量、形态、亮度与特殊结构。独眼、多眼、遮罩式光学结构必须明确。

### 机体比例
必须包含：
- 身高；
- 质量/体重（官方无精确值时允许按载具、体型与机体规格合理推定）；
- 轻/中/重/超重等机体体量描述；
- 肩、腰、胯、四肢比例；
- 女性化轮廓与装甲厚薄。

不得把身高、胸甲体量直接写成战力等级。

### 胸甲结构
必须包含字母罩杯等效视觉体量，并写清胸甲/活体机械组织与载具部件的组成关系。

推荐：`F罩杯等效视觉体量；胸甲由……形成，外轮廓……`

罩杯仅用于制卡视觉尺度，不代表赛博坦文明使用人类内衣尺码。

### 上身装甲
写胸甲、肩甲、背甲、车窗、格栅、排气管、机翼、旋翼、炮塔、装甲缝隙与涂装。不得默认布制服装。

### 下身装甲
写骨盆、腰胯、大腿、小腿、履带/轮组挂点、装甲裙片与机械关节。不得默认裙子、裤袜等人类服装。

### 外置结构
写徽记、面罩、天线、轮组、排气管、机械须、工具挂点、纪念涂装、非性征常规武装外置部件等视觉识别结构。

不得在此展开性征武装机制。

### 足部结构
写足部装甲、轮组、履带、抓地结构、推进喷口、起落结构等。不得默认鞋子或高跟鞋。

## 四、心理模型：严格保持咩咩原生格式

心理模型固定四槽、固定顺序：

```text
心理模型:
- Trauma:
- Defense:
- Trigger:
- Need:
```

不得改名，不得增加第五槽，不得改成赛博坦术语。

### Trauma
长期塑造人格的核心创伤、失败、背叛、失去、责任或战争记忆。

### Defense
角色面对压力、创伤、亲密、羞辱、失败时习惯采用的心理防御方式。

### Trigger
能够稳定触发其核心情绪、防御或行为模式的具体情境，必须可 RP。

### Need
深层心理需要，如被信任、保有自主权、被承认为完整生命、获得赎罪机会、证明自己值得追随等。

四槽必须形成因果链：`Trauma → Defense → Trigger → Need`。

## 五、对话范例

固定三句中文对话。

- 不写旁白；
- 不写同义三连；
- 必须让角色语言节奏、立场和心理模型可被模型辨识；
- 除非角色确有长期人类社会经历，不强行加入现代网络口癖。

## 六、能力条目：继续使用咩咩 `<核心设定>`

能力不得进入人物条目，统一拆为：

```text
<核心设定:【角色名】·能力>
……能力正文……
</核心设定:【角色名】·能力>
```

能力正文应按角色需要自然覆盖：

- 机体基础能力；
- 替代形态 / 变形；
- 专属性征武装模块；
- 常规武装；
- 战斗方式与战术定位；
- 特殊技术 / 遗产权限 / 独有系统；
- Energon、火种、热负荷、弹药等续航；
- 受损、过载、拆离、失联后果；
- 明确限制与不可做之事。

不要求把上述内容做成固定小标题；能力条目仍是咩咩的核心设定正文，不另造第二套 schema。

## 七、性征武装规则

- 世界内正式术语使用“性征武装 / 性征武装模块”；
- 描述生体机械结构、展开、供能、控制、拆离、损伤与修复；
- 不展开性行为描写；
- 不是所有角色都能拆离；
- 不把所有角色做成炮；
- 具体类型遵循 `docs/001_变形钢姬_人物总名册_v0.3.md`。

## 八、人物 / 能力职责边界

人物条目回答：她是谁、长什么样、为什么成为现在的她、受到什么刺激会如何反应、如何说话。

能力条目回答：她能做什么、为什么能做到、怎么战斗/变形/使用系统、代价与限制是什么。

禁止大段重复。

## 九、装配与时间线规则

- A 组核心人物进入 `worldbook/characters/main/`；
- B/C 组按重要性进入 `main/` 或 `other/`；
- 能力统一进入 `worldbook/abilities/`；
- 人物与能力共享娘化名关键词；
- 原名只作为工程检索 alias 与 `manifest/character-name-replacements.v1.json` 的输入键；
- 正式 `<world_timeline>`、事件标题、正文、参与者字段全部使用娘化名。

## 十、生产前 QA

每名角色必须通过：

1. 标签完整；
2. 字段顺序与本规范一致；
3. 不出现 `发色/发型/瞳色/上衣/下装/鞋子` 等已废弃外貌字段；
4. 不凭空生成毛发、布制服装、高跟鞋；
5. `机体比例` 有身高、质量/体重、机体轮廓；
6. `胸甲结构` 有罩杯字母等效视觉体量；
7. `光学镜 / 头部结构 / 装甲 / 足部` 与电影视觉锚点一致；
8. Trauma / Defense / Trigger / Need 完整且形成因果链；
9. 三句对话范例完整；
10. 能力拆到独立 `<核心设定:角色名·能力>`；
11. 性征武装与人物总名册 v0.3 一致；
12. 正式正文不使用原名显示角色。

## 十一、生产顺序

先生产 `何博玟` 与 `薇震天` 两套样板：人物条目 + 能力条目 + 同批 QA。样板通过后再批量生产 A24 → B31 → C14。
