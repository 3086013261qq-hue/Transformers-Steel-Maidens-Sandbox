## 二、字段职责

### 名字
只写现行娘化名。正式人物正文不得把原名当显示名。

### 性别
普通赛博坦角色统一写世界内事实：`女性（双重性征）`。不得出现“娘化”“原男性”等元叙事。

### 阵营
记录稳定阵营归属及必要的关键转阵营历史。

示例：
- `汽车人`
- `汽车人（前霸天虎）`
- `汽车人旧领袖 → 后与霸天虎合作`
- `独立赏金猎人 / 不固定隶属汽车人或霸天虎`

不得把单场临时合作误写成永久阵营。

### 定位
记录长期稳定职责、组织角色与战术定位，不写单场战果。

推荐形式：`汽车人领袖 / 重装近战 / 战略指挥`。

### 变形载具
记录主要替代形态；跨电影换型必须按时间顺序列出。

- 优先使用电影直接展示；
- 若采用官方 Hasbro 电影系玩具确认但电影未展示的形态，必须加注；
- 不得把概念设定、玩具形态和电影镜头混成同一事实等级。

### 印象
1～3 句概括第一性格印象、机体气质、最关键的历史或关系锚点。阵营、定位已有独立字段后，不必在这里机械重复。

### 头部主色
写头部装甲、机械缆线、冠状结构的主要颜色与点缀色；不得生成“发色”。

### 头部结构
写头冠、面罩、天线、鳍片、机械须、辫须、缆线、翼片等真实结构；不得凭空添加人类发型。

### 光学镜
写颜色、数量、形态、亮度与特殊结构。独眼、多眼、遮罩式结构必须明确。

### 机体比例
必须包含：
- 身高；
- 质量/体重；
- 机体规格；
- 肩、腰、胯、四肢比例；
- 装甲厚薄与整体女性化机械轮廓。

官方缺少精确质量时允许合理推定，但资料/QA 必须注明推定来源逻辑。

### 胸甲结构
必须保留字母罩杯的等效视觉体量，并描述胸甲、车窗、前舱、装甲件与活体机械组织的结构关系。

示例：`F罩杯等效视觉体量；胸甲由前舱装甲与活体机械组织共同构成，中央保留汽车人徽记。`

罩杯只作为制卡视觉尺度，不代表赛博坦文明使用人类内衣尺码。

### 上身装甲
写胸甲、肩甲、背甲、车窗、格栅、排气管、机翼、旋翼、炮塔等上半身结构。

### 下身装甲
写骨盆、腰胯、大腿、小腿、侧甲、轮组、履带等下半身结构。

### 外置结构
写具有视觉与身份意义的外置构件：徽记、面罩、天线、轮组、挂点、缆线、纪念涂装、外置工具等。

不得在这里展开性征武装的详细机制。

### 足部结构
写足部装甲、轮组、履带、抓地、起落、滑行或推进结构。

### 性征武装模块
本字段即制卡工程中所称的“扶她武器模块”，正式世界书统一使用内世界术语 `性征武装模块`。

人物条目只写：
- 模块正式名称；
- 武器/工具类型；
- 一句最核心的展开或用途特征。

示例：
`「领袖离体离子炮」：可有限拆离并重构为重型离子炮，详细机制见《何博玟·能力》。`

不得在角色条目里展开供能、冷却、拆离反馈、损伤后果等完整机制；这些全部进入对应能力条目。

## 三、心理模型：完全保留咩咩原生四槽

心理模型字段和顺序不得改变：

```text
心理模型:
- Trauma:
- Defense:
- Trigger:
- Need:
```

### Trauma
长期人格结构中的核心创伤、失败、失去、羞辱、背叛、战争记忆或无法消化的责任。不是普通弱点，也不要求角色必须患有临床 PTSD。

### Defense
面对压力、亲密、失败、威胁或创伤触发时最常使用的心理防御方式，例如控制、理性化、攻击、幽默、否认、过度承担、撤退等。

### Trigger
能稳定触发其核心情绪与防御方式的具体情境。必须可用于 RP，不写“危险”“敌人”这种空泛词。

### Need
深层而稳定的心理需要，不等于“想赢”“想杀敌”“需要 Energon”。

### 四槽联动
必须形成：`Trauma → Defense → Trigger → Need` 的人格因果链，不得四句互不相关。

## 四、对话范例

- 固定三句；
- 使用中文；
- 每句体现真实语言节奏、立场、心理模型；
- 不写旁白或“她说道”；
- 不写同义三连；
- 不无依据加入现代人类网络口癖。

## 五、能力条目

能力仍独立使用咩咩全栈核心设定格式：

```text
<核心设定:【角色名】·能力>
……能力正文……
</核心设定:【角色名】·能力>
```

能力正文原则上需要闭环交代：

- 机体规格与基础能力；
- 替代形态与变形特性；
- 性征武装模块完整机制；
- 常规武装；
- 战斗方式与战术定位；
- 特殊技术、遗产权限或独有系统；
- Energon、火种、热负荷、弹药等续航约束；
- 受损、过载、拆离或失联后果；
- 明确限制与不可做之事。

这些内容不要求机械拆成固定小标题，可按角色自然编排，但不得漏掉代价和边界。

## 六、人物条目与能力条目的职责边界

人物条目回答：
- 她是谁；
- 属于谁；
- 承担什么长期职责；
- 变成什么；
- 长什么样；
- 性征武装是什么；
- 为什么形成现在的人格；
- 她在什么情况下会怎样反应；
- 她如何说话。

能力条目回答：
- 她能做什么；
- 为什么能做到；
- 如何变形、战斗与使用性征武装；
- 特殊权限如何工作；
- 代价、限制和损伤后果是什么。

同一机制不得在人物条目和能力条目中大段重复。

## 七、硬规则

1. `阵营 / 定位 / 变形载具 / 性征武装模块` 四字段为所有正式人物条目的必填项。
2. 机械外貌字段固定为：`头部主色 / 头部结构 / 光学镜 / 机体比例 / 胸甲结构 / 上身装甲 / 下身装甲 / 外置结构 / 足部结构`。
3. 禁止再使用 `发色 / 发型 / 瞳色 / 身材 / 胸部 / 上衣 / 下装 / 配饰 / 鞋子` 旧字段。
4. `Trauma / Defense / Trigger / Need` 必须完整保留、顺序不变。
5. 固定三句对话范例。
6. 性征武装模块必须遵循 `docs/001_变形钢姬_人物总名册_v0.3.md` 现行武器锚点；若逐角精修确需调整，必须同步更新总名册与 QA。
7. 不得把所有角色做成炮，也不得反向变成全员刀剑；工具型、拘束型、电子战、医疗、工程等模块均合法。
8. 正式人物正文只使用娘化名；原名仅用于工程检索、QA 和时间线替换。
9. 正式 worldbook 不得出现“娘化”“原男性”“基于电影角色改编”等元叙事。

## 八、生产前检查清单

每名角色进入正式世界书前必须确认：

1. 标签为 `<角色名character>`；
2. 四个身份锚点字段完整：阵营、定位、变形载具、性征武装模块；
3. 九个赛博坦机械外貌字段完整；
4. 机体比例含身高、质量/体重、体态；
5. 胸甲结构含罩杯字母等效视觉体量；
6. 外貌与电影视觉锚点一致，不凭空生成人类头发、服装或鞋具；
7. Trauma / Defense / Trigger / Need 完整且成因果链；
8. 三句对话齐全且能区分角色；
9. 能力独立拆入 `<核心设定:角色名·能力>`；
10. 性征武装人物栏只做摘要，完整机制留在能力条目；
11. 能力存在真实负荷、损伤、供能与边界；
12. 原名不进入正式人物正文与正式剧情输出。
