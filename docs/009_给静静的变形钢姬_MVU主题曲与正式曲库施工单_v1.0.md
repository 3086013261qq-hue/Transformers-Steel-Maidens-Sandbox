## 3. 必须生成正式音乐 manifest

静静需生成：

`mvu/music-manifest.v1.json`

建议结构：

```json
{
  "version": 1,
  "default_track_id": "crystal-heart",
  "tracks": [
    {
      "id": "crystal-heart",
      "order": 1,
      "title": "Crystal Heart（水晶心）",
      "artist": "啃书",
      "file": "media/music/啃书 - Crystal Heart（水晶心）.mp3",
      "url": "<fixed-commit-raw>",
      "theme": true
    }
  ]
}
```

六首全部写入 `tracks`。

硬规则：

- `default_track_id` 必须为 `crystal-heart`。
- `Crystal Heart（水晶心）` 的 `theme=true`。
- 其余歌曲 `theme=false`。
- `order` 严格按本施工单 §2.1。
- `url` 使用本施工单固定 commit raw。
- manifest 只保存曲库元数据，不保存播放进度、账号信息或用户凭据。

## 4. 播放器行为冻结

继续执行 `docs/008` 的单 `<audio>` 设计，并补充：

### 4.1 单实例

- 页面生命周期内只能存在一个真实 `<audio>`。
- 切歌只修改该实例的 `src` / 当前曲目状态。
- 禁止每首歌各自创建 `<audio>`。
- 禁止切歌后残留旧音轨继续播放。

### 4.2 加载策略

- 不得页面打开时并发预载全部 6 个 MP3。
- manifest 可立即加载。
- `<audio>` 建议使用 `preload="metadata"` 或等价轻量策略。
- 只让当前曲目进入实际媒体加载流程。
- 下一首可按浏览器正常缓存机制自然缓存，不手工把整库塞进内存。

### 4.3 锁屏进入

用户点击锁屏中央进入 MVU：

1. 解锁 MVU。
2. 若没有当前曲目，选中 `crystal-heart`。
3. 在同一个用户交互链中尝试播放。
4. 成功则继续正常播放。
5. 失败则保留已选曲目和播放器 UI，显示一次轻量播放入口。

不得因为播放失败影响 MVU 解锁与阵营好感显示。

### 4.4 返回锁屏

- 返回锁屏时继续播放。
- 再次进入 MVU 不得重新从头播放。
- 不重复创建 `<audio>`。

### 4.5 切歌

曲库抽屉纵向滚动展示六首歌。

点击曲目：

- 切换当前 `src`
- 更新曲名 / 歌手
- 自动尝试播放
- 若失败，保持该曲选中状态并显示播放按钮

上一首 / 下一首严格按 §2.1 顺序循环。

### 4.6 曲目结束

默认行为：

- 当前曲目自然结束后自动进入下一首。
- 第 6 首结束后循环回第 1 首。

不做随机播放作为默认行为。

## 5. 底部音乐 dock 最终 UI

音乐仍放在单一 MVU 内页最底部，不单开页面。

默认收起态只显示：

- 当前歌曲名
- 歌手
- 上一首
- 播放 / 暂停
- 下一首
- 一个“展开曲库”按钮

展开后：

- 纵向列表
- 手机上下滑动
- 当前歌曲明确高亮
- `Crystal Heart（水晶心）` 可附加非常克制的 `主题曲` 小标签

禁止：

- 大封面墙
- 横向跑马灯导致页面横向滚动
- 六个音频元素
- 自动弹出全屏播放器
- 网易云 iframe
- 登录 / Cookie / 第三方账号功能

视觉继续服从 `docs/007`：黑 / 枪灰 / 银白为主，点色克制，不遮挡何博玟与薇震天背景主体。

## 6. 与 MVU 数据层隔离

音乐播放状态不进入：

- `<causality>`
- stat_data
- JSONPatch
- 业务世界书
- 人物 `<affinity>`

音乐是纯客户端 UI / runtime 状态。

不得为了保存当前歌曲而修改正式世界书或角色卡业务变量。

---

## 7. 容错

任一歌曲加载失败时：

- 标记该曲本次加载失败
- 显示轻量错误提示
- 不销毁播放器
- 不影响其他歌曲
- 用户可手动切换其他曲目
- 下一首逻辑可跳过本次失败曲目，避免死循环

图片、曲库或单曲媒体失败均不得导致 MVU 白屏。
